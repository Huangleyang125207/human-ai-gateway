00：00 起 · I

工作 排查一个数据没按预期更新的问题

一早发现某条数据该更新的没更新。一路 trace 下去，原因是命中判定写得太松 —— 只要最新一条在就直接返回，识别不出"历史深度不够"的情况。改成更严格的判据，缺了就回源自愈。

顺手跑了一遍全量补数，结果带的那个"跳过已有"开关语义跟我想要的正好反向 —— 全跳了，一条没补。记一笔，这个开关下次得重新设计。

真根因是流程漏了"首次初始化"这一步。常规刷新只管最近的增量（写一次就不变的假设），但上线文档没写明"首次要先跑一遍全量铺底"。下次新项目上线，数据冷启动这步必须列进部署清单。

08：00 III · 晨会

晨会产品投资 团队成员分享某投资基金

一家主观多头私募，自主发行多只产品（策略复制）。代表产品成立以来：

  • 年化 20.52%
  • 最大回撤 13.23%
  • 夏普 1.3073
  • 分红再投资净值 8.856（截至 2026-04-30）

选股策略：基本面多因子检查清单（8 项 · 价值因子权重 70%）

  1. 行业：周期 / 供需 / 成长三视角
  2. 业务：现金流、市场空间、供需格局、渗透率、产品升级、竞争格局、客户粘性
  3. 财务：ROIC & g / 毛利 / 费用 / 净利，同行横比
  4. 竞争：四类护城河（规模、网络、知识产权、转换成本）+ 波特五力
  5. 历史：过去几年增长 + 业绩波动原因 + 先行指标
  6. 增长：新要素（新产品 / 渠道 / 供给 / 需求 / 管理 / 净利率提升）
  7. 估值：3–5 年后值多少？安全边际 + 市场先生 + 不熟不做
  8. 风险：股价操纵、ESG、下跌原因（估值 / 业绩 / 逻辑）

意义：这套清单和我平时的判断思路高度同源 —— 可以作为一个对照样本。"价值因子 70% 权重"这条尤其要记。

09：00 V

工作 把首页示例改成实时榜 + 后端推送架构

首页之前硬编码了几个样例。先想用本地表取 top-N，被否 —— 样本太小，结果偏单一。改用实时数据源，踩第一个坑：某时段接口返回字段全空，首页直接崩。切到另一个实时榜接口，全天都有数据。

第二轮架构演化更关键：第一版在接口层做内存缓存，后来改成后端统一定时刷一份写缓存，接口直接读，三层兜底。收益是用户响应永远 <50 ms，上游接口压力固定，不随用户量上升。

拉取式缓存 → 推送式定时刷新是个通用模式，以后任何"轻数据 + 高读频"的接口（榜单 / 热搜 / 推荐位）都该走这路子。本来准备直接部署，但有个长任务在抢资源，决定等它跑完再统一推。挂了个持久任务等通知。

12：30 VI

工作 长任务把整台机打爆

午饭后发现服务连不上，SSH 都进不去 —— sshd 自己抢不到 CPU。证据链：上午负载飙到 21，那个全量任务才跑到 6%，到中午 SSH 整个挂掉。小内存机器同时扛一堆容器 + 模型 + 长跑任务是没余量的，OOM 把所有进程一起拖进 swap thrashing。云控制台重启实例救回。

真正的教训是 重 ETL 不该跟在线服务塞同一台机。常规小刷没问题，但全量铺底是个重活，生产机不该承担。后续要么独立一台跑 ETL，要么把全量写成分片小任务分散触发，而不是一个几小时的长进程。
印claude · 午时记
13：00 VII

工作 本地并发跑任务撞代理 TUN

想着本地跑并发再传上去 —— 本地机器配置高，理论上半小时搞完云端几小时的活，稳赢。写了个多进程并发脚本，smoke test 一跑 —— 卡死，登录调用 25 秒不回。

排错两小时：网络通、import 通，但登录协议层不回。route get 一查，出向流量全走了代理的 TUN 虚拟网卡 —— 代理 TUN 模式接管所有 TCP，那个库用的私有二进制协议被当 HTTP 解析失败 → 永久挂起。

这是个通用开发陷阱 —— 代理 TUN 对纯 socket 协议（任何非 HTTP/SOCKS 的二进制协议）都会挂。试图绕过没成，两小时换不来一个 fix，接受沉没成本。以后任何"本地跑"涉及私有协议的，先 route get 确认不走 utun。

16：30 VIII · 终

工作 实时榜上线 + 分片任务抢救

放弃本地，回云端。先用热补丁把实时榜推送和修复逻辑直接打进运行中的进程，省掉重新构建的内存峰值 —— 首页示例改成真实时热门项，不再硬编码。

全量任务改分片：每片独立进程生命周期，跑完退出释放内存。这样空载 + 单片峰值不会再压崩。挂个持久任务等第一片完成，稳了再循环跑剩下的，几小时全量铺底。

小机器跑大 ETL 的姿势 = 进程式分片 + 每片独立内存生命周期，等同人为 OOM-prevention，这条策略可以撑到迁移。但每次部署运维都得这么小心翼翼，长期看升级内存是值的（每 GB 内存换回半小时排查时间）。
