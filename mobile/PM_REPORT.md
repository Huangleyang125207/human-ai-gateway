## 四、产品决策点(给 PM 看)

### 决策 1:**桌面有的"AI 自动写日记/打卡"** 移动要做吗?

**当前状态**:移动端 AI 只能聊,不能自动调用工具。

**用户场景**:用户问"今天的鱼油吃了吗"AI 看一眼日记 → 答"没吃,要不要现在标?"用户点是 → AI 自动写入打卡。

**桌面**:✓(tool-loop 完整)。
**移动**:🟡(只能 read,不能 write through AI)。

**选项**:
- A. 现在不做,等用户反馈(估真没多少人需要)→ 0 工程
- B. 做简化版(只让 AI 调"打卡 / 加日记 entry"两个 tool)→ 1 周设计 + 1 周工程
- C. 做完整版(同桌面 5 轮 tool loop + DSML 闸 + 流式 chokepoint)→ 2-3 周

**建议**:A 先发布,看真用户调研。

### 决策 2:**Android 抠主体** 现在做还是等用户反馈?

**当前状态**:iOS 拍图自动抠主体(Vision 系统自带,免费)。Android 拍图贴原图(背景没抠)。

**影响**:Android 用户贴图时背景不透明,贴日记里不如 iOS 视觉好看。

**选项**:
- A. 现在做(MLKit Subject Segmentation,Android 12+ 自带)→ 1-2 天
- B. 等 Android 用户多了再做 → 0 工程

**建议**:Android 用户基数小的话 B;主推 Android 时一定要做。

### 决策 3:**OCR 拍补剂瓶自动填颗数** 验证后上线吗?

**当前状态**:代码 + 双平台 plugin + pill_count regex 全写完。**唯一阻塞 = 真机 5 分钟测试**。

**用户场景**:加新打卡项时拍补剂瓶 → 自动填"60 粒"meta total_pills → 用户不用手填。

**选项**:
- A. **本周内**找一台 iOS 16+ 手机 + 一瓶鱼油,拍一下验过即上线 ✓
- B. 推迟,等其他 critical 功能 first → 用户每次手填颗数

**建议**:A,5 分钟的活拖久了浪费。

### 决策 4:**桌面"留言板 / PULSE / vault 健康"** 移动要做吗?

**当前状态**:全部 ⚪ 不做。

**桌面用户场景**:翻 PULSE 仪表盘 / 21:30 看 AI 评分 / 看 vault 健康。

**移动用户**:目前**没需求**(手机用户没在手机上做项目管理 / vault 维护)。

**选项**:
- A. 维持现状,不迁 → 0 工程
- B. 优先 PULSE(项目仪表盘)在移动端做轻量版 → 1-2 周(还需重新设计移动 UI)

**建议**:A,直到用户主动要这些功能。

## 六、本次迁移做了什么(技术维度,非 PM 看)

- 桌面 80 个后端 API + 41 个 oracle 测试文件全梳理
- 移动 shim 端 45 个 endpoint,**34 个 1:1 对齐桌面**(字段 / 状态码 / 数据契约全 match)
- 30+ 次行级 fix commit(数学 / 校验 / authorship / CAS)
- iOS Vision Framework + Android Google ML Kit native plugin 双平台落地
- PARITY 收敛 ledger(每次 fix 都有 SHA + oracle 跑通证明)

## 七、推荐发版策略(给 PM 拍)

### 选项 A · 内测优先(推荐)

1. **本周**:N2 真机验完 → 发 iOS 内测版(Phase 2 真机 runbook 走完)
2. **2 周内**:邀 10-20 人内测(已有渠道:小红书内测群运营手册)
3. **1 月内**:据反馈定 chat tool-loop / Android 抠图 / OCR 是否值得 priority
4. **2 月内**:Android 公测

### 选项 B · 双平台同时

1. Android 抠图(2 天)+ iOS 真机验(0.5 天)同时做
2. **2 周内**:iOS + Android 同时内测
3. 风险:Android 反馈池小,可能浪费早期工程

### 选项 C · 全部完整再发

- chat tool-loop + Android 抠图 + PULSE 移动版 + 真机验
- **6-8 周**才能发
- 风险:错过早期反馈窗口

**建议**:A。
